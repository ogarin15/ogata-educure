## 実行前の注意

- この課題は、前のSQL基礎課題で作成した `users` / `posts` / `comments` / `likes` などのテーブルとサンプルデータが同じデータベースに存在する前提です。
- 課題文の指示どおり、`00-setup.sql` は流し直しません。既存データを消したり、テーブルを作り直したりしないでください。
- 最初に `SELECT COUNT(*) FROM posts;` を実行し、元データが20件あることを確認します。
- `01-bulk-data.sql` は9,980件を追加します。同じファイルを2回実行すると件数が増えすぎるため、必ず1回だけ実行してください。
- 追加後の投稿総数は、元が20件なら10,000件です。課題文の一部にある「10,800件」は、20 + 9,980 = 10,000 と計算が合わないため、このファイルでは10,000件を正しい目標にしています。
- SQLは `answers.sql` を上から順に進めます。ただし問8の制約追加失敗など、意図的にエラーを発生させる箇所があります。コメントを読んで、エラー後の操作を確認してください。
- 問5は重複キーエラーを意図的に発生させます。エラー後に `ROLLBACK TO SAVEPOINT` を実行してから続けてください。GUIツールによってはエラー後の実行方法が異なるため、エラーが出たら残りのSQLを選択して実行します。

## EXPLAIN ANALYZE の保存方法

各 `EXPLAIN ANALYZE` の出力をコピーし、対応する `explain-results` 内のテキストファイルに貼り付けます。

- `q02-before-index.txt`：問2、インデックス作成前
- `q02-after-index.txt`：問2、インデックス作成後
- `q03-composite-A.txt`：問3、クエリA
- `q03-composite-B.txt`：問3、クエリB
- `q10-offset.txt`：問10、OFFSET方式
- `q10-cursor.txt`：問10、カーソル方式

実行時間はPCやデータベースの状態によって変わります。課題文の目安値をそのまま書かず、自分の実測値を記録してください。PostgreSQLの実行計画は、統計情報やデータ量によって想定と異なる場合があります。

### Phase 2：トランザクション

- `COMMIT`：トランザクション内の変更を確定する。
- `ROLLBACK`：トランザクション内の変更を取り消す。
- `SAVEPOINT`：途中に戻り先を作り、`ROLLBACK TO SAVEPOINT` でその地点以降だけを取り消せる。
- `SERIALIZABLE` が必要になる例：複数の処理が同時に在庫数や予約枠を読み書きし、通常の分離レベルでは整合性のない結果になる可能性がある場合。競合時はエラーになることがあるため、アプリケーション側でトランザクションを再試行する設計が必要。

### Phase 3：制約

既存データに違反行がある状態で `ADD CONSTRAINT` を実行すると失敗する。まず `SELECT` で違反行を特定し、UPDATEで修正するかDELETEで削除し、その後に制約を追加する。

### Phase 4：更新日時・論理削除・ページネーション

- 問9の `updated_at`：更新前＿＿ / 更新後＿＿
- 全投稿数：＿＿件 / 生存投稿数：＿＿件
- 問10 OFFSET方式：＿＿ ms
- 問10 カーソル方式：＿＿ ms
- OFFSET方式は指定位置までの行を読み飛ばす必要がある。カーソル方式は直前ページの最後のキーを使って次の位置から取得するため、大きなページ番号でも効率がよい場合がある。

## 注意点

- `users` テーブルには `city` 列がありません。そのため問4の「Japan > Tokyo」は、既存スキーマに合わせて `country = 'Tokyo'` に更新しています。
- `posts.body` は元スキーマですでに NOT NULL です。問7ではNULL件数を確認したうえで、NOT NULLを再設定します。
- 問9で投稿を1件論理削除した場合、投稿総数が10,000件なら生存行数は9,999件です。課題文にある10,800件という例示値とは一致しません。
- 問10のカーソルSQLにある日時とIDは仮の値です。自分の1ページ目の20件目の `published_at` と `id` に置き換えてください。
- このフォルダーはSQL作成用のひな形です。SQLの実行結果やEXPLAINの実測値は、各自のPostgreSQL環境で取得して保存してください。
